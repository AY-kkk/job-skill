# Interview Prep Skill 接入设计

## 目标

将 `interview-prep` 完善为面向产品、AI、商业化、运营等业务岗位的研究型面试准备 Skill，并作为 `job-skill` 仓库中“面试准备”阶段的首个子集公开发布。

## 定位与边界

该 Skill 通过岗位拆解、目标公司与产品研究、竞品比较、问题预测、回答准备和行业洞察，帮助候选人形成有证据的面试准备材料。

它不是适用于所有职业的通用题库，也不负责简历修改、面试后复盘、确定性录用预测或虚构候选人经历。问题预测属于基于材料的准备优先级判断，不表述为真实面试题或“必考”结论。

## 仓库结构

```text
job-skill/

    ├── interview-deep-review/
    └── interview-prep/
        ├── README.md
        ├── SKILL.md
        ├── WORKFLOW.md
        ├── prompts/
        │   ├── README.md
        │   └── 01—08 模板文件
        └── scripts/
            ├── README.md
            ├── product_extractor.py
            └── product_scraper.py
```

- 根 `README.md` 先更新“面试准备”状态和当前 Skill 索引。
- 子集 `README.md` 面向使用者说明定位、材料、输出、使用方式和限制。
- `SKILL.md` 负责触发、路由、证据规则和工作流入口，详细步骤保留在 `WORKFLOW.md`。
- `prompts/` 保留原有八个模板，修正其中的过度确定性和事实边界。
- `scripts/` 保留两个可选辅助脚本，并完成必要的网络与依赖安全加固。

## 内容完善

1. 将 Skill 描述和正文定位收窄到产品、AI、商业化、运营等业务岗位。
2. 删除没有评测依据的提取准确率、固定问题权重、固定耗时和“几乎 100% 必考”等表述。
3. 将准备材料中的内容区分为已验证事实、基于证据的推断、候选人观点和待确认信息。
4. 公司、产品、竞品、定价和行业动态记录来源 URL 与查询日期；关键结论优先交叉验证。
5. 回答模板只能使用简历或用户确认的事实。需要数字、经历或个人贡献而材料不足时，生成澄清问题，不补写成绩。
6. 预测问题按证据来源与准备优先级排序，不伪装成面试官真实意图。
7. 研究范围按用户时间选择快速、标准或专项模式，不强制每次生成全部文件。

## 脚本安全

`product_scraper.py` 只接受公开的 HTTP/HTTPS 页面：

- 拒绝无效协议、包含凭据的 URL、localhost、环回、私有、链路本地、保留和未指定地址；
- DNS 解析后的全部地址也必须为公开地址，跳转目标需重新校验；
- 限制跳转次数、响应体大小和可接受的 HTML 内容类型；
- 使用可识别的通用 User-Agent，不伪造 Google Referer；
- 网络失败时跳过当前页面并说明原因，不关闭 TLS 验证或绕过站点限制。

脚本说明不使用 `--break-system-packages`，改为虚拟环境或 `uv` 的隔离安装方式。Playwright 未被脚本使用，因此不列为当前依赖。

## 错误处理

- 缺少 JD、简历或目标公司信息时，只请求会影响当前模式的必要材料。
- 无法访问网页时，记录失败来源并允许用户提供页面文本，不凭模型记忆补齐时效性事实。
- 信息冲突时并列来源和日期，说明尚不能确认的内容。
- 脚本输入配置错误时返回清晰错误和非零退出码，不输出伪成功结果。

## 验证方式

按用户要求，不新增脚本测试文件或测试套件。发布前执行：

- Skill 规范校验与自动审查；
- Python `py_compile` 语法检查；
- 两个脚本的 `--help` 冒烟检查；
- 静态依赖、提示注入、敏感信息和网络行为扫描；
- Markdown 空白、内部链接、目录清单和 Git 状态检查；
- 推送后从 GitHub 公开地址回读根 README、子集 README 和 `SKILL.md`。

验证不访问真实产品网站，也不运行实际抓取任务。

## 交付顺序

1. 先修改并提交根 `README.md`。
2. 再接入并提交完善后的 `skills/interview-prep/`。
3. 完成本地验证后推送到 `main`。
4. 核对远端提交哈希和公开文件内容。
