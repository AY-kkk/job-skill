# Interview Deep Review｜面试深度复盘

把一场已经结束的面试，从“我感觉答得不太好”变成一份有原文依据、能指导下一次行动的复盘报告。

`interview-deep-review` 会从面试逐字稿中还原全场结构，逐题检查回答质量，识别反复出现的表达或证据问题，并进一步生成下一轮面试的准备方案。它还会默认扫描面试暴露出的知识缺口；有明确证据时，进一步补齐相关知识框架、适用边界、可靠案例和追问准备。

它关注的不只是某一道题该怎么重答，更关注候选人的岗位人设、经历证据和表达方式是否前后一致，以及回答背后的知识是否足以承接下一轮追问。

## 适合什么时候用

- 一面或二面结束后，想系统判断自己的表现。
- 面试官追问很多，但不知道是在感兴趣还是在核实疑点。
- 回答中有项目、数据或个人贡献，想检查证据链是否完整。
- 面试暴露了概念、指标、产品机制、商业模式或行业知识缺口，需要在下一轮前补齐。
- 已经进入下一轮，需要把本轮暴露的问题转成备战材料。
- 多次面试出现相似问题，想找到更底层的表达模式。

如果只是打磨一道面试题，也可以使用，但完整八步流程更适合有逐字稿的整场复盘。

## 你需要提供什么

| 材料 | 必需程度 | 作用 |
|---|---|---|
| 面试逐字稿 | 深度复盘必需 | 还原原问题、原回答、追问和时间线 |
| 录音或视频 | 可替代逐字稿 | 需要当前 Agent 具备可用的转写能力 |
| 目标岗位 JD | 推荐 | 判断回答是否真正关联岗位要求 |
| 本次使用的简历 | 推荐 | 核对项目、数据和候选人定位 |
| 公司、轮次、面试时长 | 可选 | 帮助补齐报告背景 |
| 下一轮时间与面试官信息 | 可选 | 让备战建议更有针对性 |

只有回忆笔记而没有逐字稿时，仍可以做有限复盘，但不能可靠判断完整题目、打断、追问链和原话信号。Skill 会明确标注这一限制，而不是补写不存在的对话。

## 它会怎么工作

1. **准备材料**：取得逐字稿，校对公司名、人名、产品名和关键数字，并区分说话人。
2. **扫描全场**：还原面试阶段、时间分配、主题转移、开场与收尾。
3. **逐题拆解**：逐道分析原问题、回答摘要、有效证据、丢分风险和改进方向。
4. **专项分析**：检查追问模式、面试官复述、反问质量、数据使用和人设一致性。
5. **核心知识深研**：每次默认扫描知识缺口；有逐字稿或 JD 证据时，选择最多五个主题，补齐知识框架、边界、可靠案例、口述回答和追问准备。
6. **系统诊断**：将反复出现的问题聚类为 3—5 个底层模式，而不是堆砌零散建议。
7. **下一轮备战**：重写关键回答，吸收知识深研结论，准备追问层、预测难点题并升级反问清单。
8. **形成行动清单**：按立即修正、下一轮面试前和长期训练三个时间尺度安排动作。

## 你会得到什么

默认输出一份 Markdown 报告，通常包括：

- 全场总评与核心依据；
- 关键问题逐题复盘；
- 亮点资产与可继续强化的标签；
- 3—5 个系统性问题及根因；
- 面试官信号与追问链解读；
- 关键问题的优化回答；
- 有证据触发时的核心知识深研章节或独立报告；
- 下一轮难点题、反问和准备材料；
- 可执行的短期与长期行动清单。

报告深度会随材料完整度和用户目标调整。逐字稿很长时，可以先输出全场诊断，再按优先级展开关键题，避免为了“题题都写”而降低分析质量。

## 默认知识深研如何执行

每次复盘都会扫描候选人回答中的知识缺口，但不代表每场面试都强制生成研究题目。只有出现以下证据之一时才进入深研：候选人明确表示不知道或无法解释；回答存在概念、边界或选型问题；面试官明确纠正或反复要求解释；相关知识与 JD 核心职责直接相关；或候选人明确指定需要补研。

深研主题最多五个，也可以为零。同一知识块下的多个问题会合并处理；没有合格主题时，报告会说明“本场未发现需要专项深研的知识缺口”及判断依据，不会为了显得完整而凑题。

研究范围不限于开发或算法知识，也包括产品机制、业务流程、指标定义、商业模式、客户与渠道和行业知识。每个主题会说明原问题与触发证据、知识缺口、核心框架、适用边界、可靠案例、可口述回答和继续追问。产品功能、公司案例、行业数据等时效性内容会保留来源和查询日期。

## 证据边界

Skill 会把判断分为三类：

- **逐字稿事实**：能在输入中找到原话、时间戳或明确上下文。
- **分析推断**：由追问方式、回答结构和岗位要求推导出的解释，需要说明依据和不确定性。
- **信息不足**：材料不支持判断，直接说明缺什么，不猜测。

面试官说“好的”“明白”、打断回答或连续追问，都可能有多种原因。它们可以成为分析线索，但不能单独证明面试通过、失败、怀疑造假或对候选人感兴趣。最终招聘结果也不会由本 Skill 保证。

外部研究只能补充知识，不能替候选人补写项目、数字、客户或个人贡献。逐字稿、简历和未公开项目内容不会被直接放入公开搜索词；无法验证的案例和“最新”结论不会写成事实。

## 安装

克隆仓库后，以 Codex 为例：

```bash
cp -R skills/interview-deep-review ~/.codex/skills/
```

不同 Agent 的 Skills 路径可能不同，请按对应产品的加载方式调整。

## 调用示例

```text
请使用 $interview-deep-review 复盘这场产品经理一面。
我会提供逐字稿、当时使用的简历和岗位 JD。
请重点检查项目数据是否说清楚、个人贡献边界是否可信，
并帮我准备三天后的二面。
```

如果只有录音，可以这样开始：

```text
请使用 $interview-deep-review。先确认当前是否能转写这份录音；
如果不能，请告诉我需要提供什么格式的逐字稿，不要根据录音文件名猜测内容。
```

## 不适用或需要谨慎的场景

- 没有任何面试记录，只能依赖模糊回忆，却要求逐题还原。
- 要求预测确定的录用结果。
- 要求虚构项目、业绩、数据或个人贡献来“优化”回答。
- 把未经验证的公司传闻或行业动态直接写入备战材料。
- 未经本人同意处理包含第三方隐私的录音或逐字稿。
