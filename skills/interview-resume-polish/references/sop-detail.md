# 六步 SOP 详细操作与检查清单

> SKILL.md 的精简版流程在此展开。按顺序执行，每步的"交付检查"不通过不进入下一步。

---

## 第 0 步 · 素材归属校验（前置关卡）

**输入**：用户提供的全部素材（简历文件、项目文档、飞书链接、截图、口述）

**动作**：
1. 列出全部素材清单，标注来源方（本人的 / 他人的 / 共享的）；
2. 对每个素材提取身份指纹（姓名、邮箱、电话、学校、毕业时间、文档更新人）；
3. 与目标候选人比对；
4. 归属不明时，输出确认表请用户裁决，**不要猜测**。

**交付检查**：
- [ ] 每个素材都有明确归属
- [ ] 存疑素材已排除或已获用户确认

---

## 第 1 步 · 输入诊断

**输入**：候选人简历原文（该候选人所属的素材）

**动作**：
1. 逐条抄录原文（保留原始数字，不改动）；
2. 输出问题清单，逐条给修正方向；
3. 必答三问：
   - 差异化经历是否被埋没？（如"从 0 到 1 搭平台"被写成零散流程优化）
   - 提供的素材里有哪些成果/数据没用上？
   - 同一经历是否存在多版表述，哪版更强？

**交付检查**：
- [ ] 原文数字完整抄录、未改动
- [ ] 问题清单覆盖：结构 / 内容 / 表达 / 事实四类
- [ ] 亮点挖掘三问已回答

---

## 第 2 步 · 岗位解码（含竞品调研）

**输入**：目标岗位 JD、行业信息

**动作**：
1. **JD 拆解**：区分硬性要求 / 隐性要求 / 加分项；
2. **竞品调研**（两条赛道）：
   - 公司产品竞品：了解业务与差异点（供面试谈资）
   - 人才画像竞品：同类岗位优秀履历的能力构成（供简历输入）
3. **产出能力坐标系**：行业公认的能力维度 + 通用术语词典。

**关键纪律**：
- 调研对象是**行业通行方法论**，不是竞品的产品功能清单；
- 竞品/行业信息**必须来自当次任务的联网搜索**，不得引用技能文件内正例或历史会话中的既有数据充当事实；
- 调研所得竞品方法论只作坐标系与面试谈资，简历事实一律以用户上传素材为准；正确动作是"翻译"——用坐标系语言重写本人经历；
- 竞品公司名不进简历正文。

**交付检查**：
- [ ] JD 三类要求已拆分
- [ ] 能力坐标系已产出（维度 + 术语）
- [ ] 本人经历已能映射到坐标系

---

## 第 3 步 · 经历盘点

**输入**：原始素材（项目文档、飞书链接、口述补充）

**动作**：
1. 按模块拆解每段经历的事实要素（问题 / 动作 / 数据 / 协作方 / 时间）；
2. 逐条标注数据出处；
3. 输出缺口清单（缺什么数据、从哪取证）。

**交付检查**：
- [ ] 每个数字有出处
- [ ] 缺口清单已列（含取证来源建议）
- [ ] 无编造、无外推

---

## 第 4 步 · 匹配映射

**输入**：素材库 + 能力坐标系

**动作**：
1. 建能力矩阵：能力维度 × 证据 × 强度（强 / 中 / 弱）；
2. 标出差距（坐标系有但本人无证据的维度）；
3. 给出取舍建议（哪些经历前置、哪些弱化）。

**交付检查**：
- [ ] 每段经历对应到具体能力维度
- [ ] 差距与取舍策略明确

---

## 第 5 步 · 重构表达

**输入**：素材库 + 能力矩阵

**动作**：
1. **文风基准判定**（先做）：按 `style-guide.md` 第〇节——有范例按范例提炼；互联网产品/产运/销售岗默认五铁律；其他岗位/语言先与用户确认后再动笔；
2. **结构**：按能力视角拆分模块（如 平台设计 / 技术纵深 / 用户运营）；
3. **文风**：按 `style-guide.md` 五铁律重写；
4. **量化**：指标前置、加粗、箭头式串联；
5. **STAR 补全**：确保每个模块有 T（任务目标），T 内嵌在行动中而非独立成句。

**交付检查**：
- [ ] 文风基准已判定（范例 / 默认五铁律 / 用户确认）
- [ ] 模块按能力视角拆分，标题为「标签：」
- [ ] 无独立背景句，痛点已融入行动
- [ ] 单模块 150–210 字
- [ ] 数字加粗，缺口标〔待补〕
- [ ] STAR 四要素完整

---

## 第 6 步 · 校验迭代

**输入**：润色稿

**动作**：
1. **STAR 检验**：逐模块打勾 S/T/A/R，缺项回炉；
2. **流畅度诊断**：
   - 纸面：模块顺序即叙事主线（如"建平台 → 通数据 → 运营人"）
   - 口头：写 60 秒电梯陈述，通读是否顺
3. **穿帮排查**（三类）：时间线 / 名称口径 / 职责边界；
4. **三轮收敛**：结构轮 → 文风轮 → 事实轮，每轮记录版本号。

**交付检查**：
- [ ] STAR 四要素全齐
- [ ] 60 秒口述通顺
- [ ] 三类穿帮已排查并列出风险提示
- [ ] 待补清单与风险提示随稿交付

---

## 迭代收敛机制（重要）

简历润色**不是一次成稿**，而是在三个维度上螺旋收敛。预期各维度会有 1–3 轮往返：

| 维度 | 典型迭代 | 收敛标志 |
|---|---|---|
| 结构与内容 | 模块拆分方式、成果归属修正 | 模块按能力视角划分，无归属错位 |
| 文风与表达 | 范例锚定 → 压缩 → 背景融入 | 符合五铁律，单模块 ≤210 字 |
| 事实与归属 | 数据核对、素材清洗 | 只含本人素材，数字与原文一致 |

**收到用户范例时的处理**：立即反向提炼为可执行规范（本次从一段范例提炼出 5 条铁律），写入 style-guide.md 并应用于全部模块——**范例锚定比规则描述更有效**。
