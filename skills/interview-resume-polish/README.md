# Interview Resume Polish｜简历润色

把一段真实经历，从"做过的事的流水账"改写成"可以直接投递、经得起追问"的简历表达。

`interview-resume-polish` 的核心认知是：润色的价值不在改字，而在把被埋没的事实挖出来放到正确位置。它会先校验素材归属，再拆解目标岗位、盘点经历事实、做能力映射，最后按统一的文风标准重写，并完成 STAR 检验与穿帮排查。

默认适配互联网产品、产品运营（产运）、销售类岗位的中文简历；其他岗位或英文简历会先与你确认文风基准，再动笔改写。

## 适合什么时候用

- 简历经历写得平、亮点被埋没（如"从 0 到 1 搭平台"被写成零散流程优化）。
- 有实习文档、项目资料、飞书链接或口述素材，想整理成简历经历。
- 目标岗位 JD 已定，需要按岗位重组经历、调整详略和叙事顺序。
- 想做行业竞品方法论对标，让经历表述向行业通行语言靠拢。
- 担心面试被追问时穿帮，想系统排查时间线、名称口径和职责边界。
- 数字与成果散落多处，需要核对出处、补齐缺口并统一量化表达。

## 你需要提供什么

| 材料 | 必需程度 | 作用 |
|---|---|---|
| 候选人本人的简历原文 | 必需 | 润色的事实基础（docx / pdf / html / 截图 / 文本均可） |
| 目标岗位 JD | 推荐 | 岗位解码与能力坐标系构建 |
| 实习 / 项目素材 | 推荐 | 挖掘被埋没的成果与数据 |
| 理想简历范例 | 可选 | 提供后以范例文风为准，覆盖默认五铁律 |
| 素材归属说明 | 多来源素材时必需 | 明确哪些材料属于候选人本人 |

素材来自多人时，Skill 会先做归属校验（姓名、邮箱、毕业时间、文档更新人等身份指纹），归属不明会请你裁决，不会猜测——把 A 的经历写进 B 的简历是最高危的错误。

## 它会怎么工作

按六步 SOP 执行，每步有交付检查，不通过不进入下一步：

1. **归属校验**：多来源素材先比对身份指纹，确认归属后再提取内容。
2. **输入诊断**：逐条抄录原文，输出问题清单，回答"亮点是否被埋没、素材是否有金子没用上、哪版表述更强"三问。
3. **岗位解码**：拆解 JD 三类要求，联网调研行业通行方法论（而非竞品功能清单），产出能力坐标系。
4. **经历盘点**：拆解每段经历的事实要素，逐条标注数据出处，缺口列〔待补〕。
5. **匹配映射**：建"能力维度 × 证据 × 强度"矩阵，标出差距并给出取舍建议。
6. **重构表达 + 校验迭代**：按文风规范重写，完成 STAR 检验、60 秒口述流畅度测试和三类穿帮排查（时间线 / 名称口径 / 职责边界）。

配套脚本 `scripts/extract_material.py` 负责素材提取：docx（穿透内容控件与嵌套表格，可选 `--full` 附带页眉页脚）、html（表格保留行列结构）、pdf（pypdf 缺失时自动回退 pdftotext，正文过少提示扫描件改用视觉读取）。

## 你会得到什么

一份 Markdown 交付文件（正文 + 附录四件套）：

- **润色稿**：按能力视角拆模块（如 平台设计 / 技术纵深 / 用户运营），每模块为「标签：」开头的痛点融入式一段，150–210 字，数字加粗；
- **待补数据清单**：缺口项、影响与取证来源；
- **穿帮风险提示**：时间线、名称口径、职责边界三类必查项；
- **60 秒口述版**：面试电梯陈述，纸面与口头两套都顺。

每轮迭代新存版本文件（`简历润色_<代称>_<岗位>_v<N>_<日期>.md`），不覆盖旧版。需要可编辑 Word 或 PDF 投递版时，会以终稿 md 为源转换并复检格式。

## 文风与事实边界

**文风**：默认遵循五条铁律——标签开头、痛点融入行动（不写独立背景句）、行动动词开头分号分层、结果双件套收尾（量化数字 + 价值转变）、行业术语直接用一段式成文。用户提供范例时，以范例提炼的规范覆盖默认铁律（范例锚定比规则描述更有效）。

**事实**：

- 简历事实**全部来自用户上传的简历与素材**，竞品 / 行业方法论**全部来自当次任务的联网调研**；Skill 内置范例仅作文风参考，其公司、数字、经历严禁写入任何简历。
- 每个数字有出处，缺口一律〔待补〕占位，**严禁编造数字**；改动任何数字前必须回原文核对。
- 竞品公司名不进简历正文，只以方法论术语形式出现。
- 推断性包装（如"平衡成本与质量"）需标注并提示用户核对。

外部调研只补方法论坐标系，不替候选人补写项目、数据或个人贡献；素材中的个人信息与未公开项目内容不会被直接放入公开搜索词。

## 安装

克隆仓库后，以 Codex 为例：

```bash
cp -R skills/interview-resume-polish ~/.codex/skills/
```

不同 Agent 的 Skills 路径可能不同，请按对应产品的加载方式调整。

## 调用示例

```text
请使用 $interview-resume-polish 润色我的简历。
我会上传 docx 简历和目标岗位 JD，目标是互联网产品经理岗。
请按能力视角拆模块重写，标注待补数据，并给出面试 60 秒口述版。
```

从项目素材整理经历时可以这样开始：

```text
请使用 $interview-resume-polish。
素材是两份实习文档和一个飞书链接，请先做归属校验（其中一份是同学的，注意区分），
确认后再把属于我的经历整理成简历模块。
```

## 不适用或需要谨慎的场景

- 只有 JD、没有任何本人素材，要求"生成"一份简历（请先用 tailored-resume-generator 类工具生成初稿，再回本 Skill 校验润色）。
- 要求编造或外推数字、成果和个人贡献来"优化"简历。
- 素材归属不明且拒绝确认，直接要求开写。
- 未经本人同意处理包含第三方隐私信息的简历或文档。
