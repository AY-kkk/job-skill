# Interview Prep｜研究型面试准备

面向产品、AI、商业化、运营等业务岗位，把零散的 JD、简历和公司信息整理成一套有证据、能口述、可按优先级执行的面试准备方案。

`interview-prep` 不只是生成一份通用题库。它会先判断目标岗位真正需要什么，再研究公司的产品、用户、商业模式和竞争环境，最后把研究结论连接到候选人的真实经历，形成问题优先级、回答框架、反问和准备行动。

## 适合哪些岗位

- 产品经理、AI 产品经理、平台产品、策略产品；
- 商业化、增长、市场、销售策略与解决方案；
- 用户运营、内容运营、产品运营和行业运营；
- 需要理解公司业务、产品和竞争格局的其他业务岗位。

它不定位为算法、开发等纯技术岗位的刷题工具，也不负责简历改写或面试结束后的逐字稿复盘。

## 需要提供什么

| 材料 | 必需程度 | 用途 |
|---|---|---|
| 目标岗位 JD | 必需 | 拆解职责、要求和考察证据 |
| 公司与岗位名称 | 必需 | 确定研究对象和输出语境 |
| 本次使用的简历 | 推荐；生成个人回答时必需 | 找岗位证据、经历疑点和追问入口 |
| 面试轮次与准备时间 | 推荐 | 决定准备深度和优先级 |
| 招聘方已提供的材料 | 可选 | 补充团队、产品或面试流程信息 |

没有简历时仍可做岗位和公司研究，但不能生成带有个人项目、数据或贡献的回答。

## 三种使用模式

### 快速模式

适合准备时间紧张。只做岗位核心定位、目标产品速览、高优先级问题、五个左右的回答框架和反问清单。

### 标准模式

完成岗位拆解、公司与产品研究、主要竞品对比、简历证据映射、问题优先级、回答框架、行业观点和行动清单。

### 专项模式

只处理一个明确问题，例如竞品研究、商业模式分析、产品体验题、简历项目追问、回答打磨、深度追问演练或终面行业观点。

## 工作流程

1. **岗位拆解**：区分 JD 原文事实和对岗位级别、汇报关系、面试重点的推断。
2. **目标研究**：研究公司、产品、用户、场景、定价和商业模式，记录来源与查询日期。
3. **竞品分析**：先定义竞争维度，再选择直接、间接和替代方案，不为凑数量加入伪竞品。
4. **证据映射**：把岗位要求映射到简历中的真实项目、动作、数据口径和个人贡献。
5. **问题准备**：按证据强弱和岗位重要性确定准备优先级，并为关键问题准备追问层。
6. **表达与行动**：形成可自然口述的回答框架、双向判断的反问，以及面试前行动清单。
7. **可选深度问答**：对少量核心问题进行事实盘点、分层追问和回答一致性检查。

详细步骤见 [`WORKFLOW.md`](WORKFLOW.md)。九个可选模板位于 [`prompts/`](prompts/)；它们是可修改的工作材料，不要求每次全部使用。

## 主要输出

根据所选模式，输出可以是一份整合报告，也可以拆成多个 Markdown 文件：

- 岗位定位与能力证据表；
- 目标公司、产品和商业模式研究；
- 竞品选择依据与差异分析；
- 简历证据映射和待补充问题；
- 面试问题优先级与追问方向；
- 基于真实经历的回答框架；
- 可选的深度问答手册：事实盘点、主回答、代表性分层追问和一致性检查；
- 行业观点、反方证据与适用语境；
- 反问清单和面试前行动清单。

## 事实和预测边界

研究材料将内容分为：

- **已验证事实**：能回溯到 JD、简历原文或公开来源，并保留 URL 与查询日期；
- **基于证据的推断**：从职责、产品信息或竞争环境推导，明确说明依据；
- **候选人观点**：为面试表达准备的个人判断，不包装成公司立场；
- **待确认信息**：材料不足或来源冲突，列出需要补充的问题。

“问题预测”表示值得优先准备的问题，不代表面试官一定会问。回答不会新增用户未确认的项目、数字、客户、成果或个人贡献。

## 安装与调用

以 Codex 为例：

```bash
git clone https://github.com/AY-kkk/job-skill.git
cp -R job-skill/skills/interview-prep ~/.codex/skills/
```

调用示例：

```text
请使用 $interview-prep，按标准模式准备这场 AI 产品经理面试。
我会提供 JD、简历和面试时间。请先拆岗位，再研究公司和产品；
所有时效性结论保留来源与查询日期，不要替我编造量化成果。
最后对证据最薄弱的核心问题做深度追问演练，先列出需要我确认的信息。
```

## 辅助脚本

[`scripts/`](scripts/) 中包含两个可选工具：

- `product_extractor.py`：从已经取得的页面文本中做规则化初步提取；
- `product_scraper.py`：抓取公开的静态 HTML 产品页。

正式研究优先使用能保留来源的搜索和浏览工具。抓取脚本不适合登录后页面、内部系统、含隐私材料的链接或主要依赖 JavaScript 渲染的网站；运行前还应确认网站条款与 robots 规则。

## 使用提醒

- 简历包含个人信息，不要把完整简历或联系方式放入公开搜索词。
- 公司、产品、定价和行业情况会变化，面试前应复查关键结论。
- 研究的目标是帮助你形成判断，不是背诵看起来专业的固定话术。
- 生成材料不能替代候选人本人对经历真实性和保密义务的确认。
