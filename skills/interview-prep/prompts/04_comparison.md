# Prompt 04: 竞品横向对比分析

## 用途
基于多个产品的结构化数据，生成横向对比分析报告。

## 输入变量
- `{{target_product}}` — 目标产品名称
- `{{products_json}}` — 多个产品的结构化JSON数据数组

---

## Prompt 内容

你是一位资深的ToB产品分析师，擅长做竞品横向对比分析。

以下是 {{target_product}} 及其竞品的结构化数据，请生成一份深度对比分析报告。

```json
{{products_json}}
```

## 输出要求

### 一、产品概览表
用一张表格展示各产品的核心信息对比，维度包括：
- 产品名称
- 所属公司
- 一句话定位
- 目标客户
- 部署方式
- 核心功能数量
- 应用场景数量

### 二、核心能力维度对比
选取最关键的能力维度做横向对比。每个单元格使用“已验证支持 / 已验证部分支持 / 来源未提及 / 来源冲突”，并附来源编号；“来源未提及”不能写成“不具备”。

维度选择建议（根据产品类型调整）：
- 自然语言交互能力
- 数据分析/洞察能力
- Agent自主规划能力
- 知识库/RAG能力
- 多模型支持
- 私有化部署
- 开放集成能力（API/SDK）
- 行业解决方案
- 评测/监控能力
- 安全合规能力

### 三、差异化分析
分别分析：
1. **目标产品的差异化优势**：和竞品相比，独特的亮点是什么？
2. **目标产品的短板**：哪些方面不如竞品？
3. **各竞品的差异化定位**：每家分别主打什么？

### 四、竞争格局判断
- 市场格局是怎样的？（一超多强 / 两强争霸 / 群雄逐鹿）
- 各家的竞争策略有什么不同？
- 未来的竞争焦点会是什么？

本节属于基于证据的推断。写出依据、反方证据和仍待确认的信息，不把分类框架包装成市场事实。

### 五、面试可能问到的竞品问题
列出 5-8 个面试中可能被问到的竞品相关问题，并给出回答要点提示。

要求：
- 客观中立，不贬低任何产品
- 每个重要结论都要有输入数据或来源支撑；缺少证据时明确标注
- 分析要有深度，不只是罗列事实
- 用 Markdown 格式，结构清晰
