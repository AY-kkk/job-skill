# Job Skill

一套围绕完整求职流程持续建设的 Agent Skills 集合。

求职不是“改好一份简历”或“背完几道面试题”就结束了。它通常包含职业定位、经历梳理、简历制作、岗位匹配、投递管理、面试准备、面试复盘和 Offer 决策等一连串任务。这个仓库希望把其中适合由 AI 协助的工作沉淀为可复用、可组合的 Skills，让每一次准备都有方法，也能留下下一次继续使用的成果。

## 求职流程能力地图

仓库将沿着以下流程逐步补充 Skills：

| 阶段 | 可以解决的问题 | 当前状态 |
|---|---|---|
| 职业定位 | 盘点经历、识别优势、确定目标岗位 | 规划中 |
| 简历与材料 | 重组经历、优化简历、准备作品集和求职信 | 规划中 |
| 岗位研究 | 拆解 JD、评估匹配度、研究公司与业务 | 规划中 |
| 投递管理 | 记录进度、安排跟进、沉淀岗位信息 | 规划中 |
| 面试准备 | 研究岗位、公司、产品与竞品，确定问题优先级并打磨回答 | 已收录首个 Skill |
| 面试复盘 | 从逐字稿中识别表现、问题和改进动作 | 已收录首个 Skill |
| Offer 决策 | 比较机会、评估风险、准备谈薪 | 规划中 |

这里展示的是仓库的建设方向，不代表所有能力都已经完成。可直接使用的内容请以“当前已收录”为准。

## 当前已收录

| Skill | 用途 | 输入 | 主要输出 |
|---|---|---|---|
| [`interview-prep`](skills/interview-prep/) | 面向产品、AI、商业化、运营等业务岗位，完成岗位拆解、公司与产品研究、竞品分析、问题预测和回答准备 | JD、简历、目标公司与准备时间 | 岗位分析、研究材料、问题优先级、回答框架和行动清单 |
| [`interview-deep-review`](skills/interview-deep-review/) | 对一场面试进行证据驱动的深度复盘，并为下一轮形成行动方案 | 面试逐字稿；也可附 JD、简历和背景信息 | 全场分析、逐题复盘、系统性诊断、下一轮准备和行动清单 |

## 如何使用

### 1. 获取仓库

```bash
git clone https://github.com/AY-kkk/job-skill.git
cd job-skill
```

### 2. 安装需要的 Skill

以 Codex 为例，可以将目标目录复制到个人 Skills 目录：

```bash
cp -R skills/interview-prep ~/.codex/skills/
cp -R skills/interview-deep-review ~/.codex/skills/
```

不同 Agent 的 Skills 目录和加载方式可能不同，请以对应产品的说明为准。你也可以不安装，直接把目标 `SKILL.md` 作为工作流程说明提供给 Agent。

### 3. 发起任务

可以显式指定 Skill：

```text
请使用 $interview-prep，结合我的简历和 JD，准备这场 AI 产品经理面试。

请使用 $interview-deep-review，基于这份逐字稿复盘我的一面表现，并帮我准备下一轮。
```

也可以直接描述需求；支持 Skill 自动发现的 Agent 会根据 `SKILL.md` 中的触发说明判断是否调用。

## 目录结构

```text
job-skill/
├── README.md
└── skills/
    ├── interview-prep/
    │   ├── README.md
    │   ├── SKILL.md
    │   ├── WORKFLOW.md
    │   ├── prompts/
    │   └── scripts/
    └── interview-deep-review/
        ├── README.md
        └── SKILL.md
```

每个 Skill 都是一个相对独立的目录：

- `README.md` 面向使用者，解释它适合解决什么问题、需要什么输入、会交付什么结果。
- `SKILL.md` 面向 Agent，定义触发场景、执行方法、证据边界和输出要求。
- 只有在实际工作需要时，Skill 才会增加 `scripts/`、`references/` 或 `assets/`。

## 使用原则

- AI 可以帮助梳理和训练，但不能替你编造经历、数据或项目贡献。
- 简历、逐字稿、Offer 等材料可能包含个人信息；使用前请确认所选工具的数据与隐私设置。
- Skill 给出的评分、面试官信号和录用倾向只是辅助判断，不是招聘结果的保证。
- 对公司、岗位和行业现状有时效要求时，应补充可靠来源并标注查询时间。
